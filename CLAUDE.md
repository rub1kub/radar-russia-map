# Карта обстановки — правила проекта

## Философия
- Минимализм превыше всего: ничего не перегружать. Новая информация на
  экране должна заслужить своё место; техподробности живут в подсказках
  и «О проекте», а не на главном экране.
- Карта утверждает только то, что сказали источники. Числа целей, маршруты,
  сигналы не выдумываются: прогноз («внимание по фиксациям», «приготовиться
  к атаке», «двигается на…») — не фиксация; точечное событие не красит
  весь регион.
- Региональное показывать тем, кому оно релевантно (мост — в карточке
  Крыма, а не в общей шапке).

## Предметный контекст
- Пороги, иконки и физика выцветания считаются от украинских дальнобойных
  БПЛА самолётной схемы (~150 км/ч: Хорнет, Бобр, Дартс, Лютый) — не от
  FPV и не от «Гераней». Район борт пересекает ~за полчаса, регион ~за 3 часа.
- Класс caution («меры безопасности», «внимание») на карту не идёт —
  решение владельца. Паттерн в классификаторе оставлен как перехват.
- Групповые имена (Приазовье, Причерноморье) разворачиваются в районы
  только при известном регионе — гадать нельзя.

## Где что работает
- Боевой сайт — https://tihoenebo.com (Нидерланды, Ubuntu). Там же **весь
  конвейер**: systemd-юниты tihoenebo-poll (сбор), tihoenebo-pipeline
  (разбор), tihoenebo-api (порт 8010, 8000 занят чужим контейнером),
  tihoenebo-retention.timer (чистка корпуса).
- Дома — только разработка: API на 8000 и vite. **Сбор дома запускать
  нельзя**: сессия Telegram одна на аккаунт, второй клиент ломает
  серверный. По той же причине нет заливки базы на сервер — данные
  рождаются там. Свежую базу для отладки: ./scripts/pull-db.sh
- На сервере живут чужие сайты (ton4.pro, tonsuite.org) и docker-стек —
  их конфиги и порты не трогать.

## Рабочий процесс
- CI нет намеренно (GitHub Actions запрещён). Перед пушем: ./scripts/check.sh
  (pytest + vitest + tsc). Пуш руками.
- Выкатка: ./scripts/deploy.sh (проверки, сборка фронта локально — на
  сервере node 18, а Vite нужен 20+, — git pull на сервере, рестарт API).
- Каналы Telegram опрашивать по chat_id, не по username: имена меняются.
- Секреты и данные (ingest/.env, *.session, ingest/data/) в git не попадают.
